## AI Diary

This was a deceptively simple task that revealed an infrastructure documentation gap. The user asked to add a group to "both local and remote" — straightforward, except I had no idea how to reach the EC2 instance. I burned several minutes cycling through SSH keys and usernames on three different IP addresses before the user handed me the right key (`e2c-crawler.pem`). The naming convention didn't help — `openclaw-ec2.pem` sounded right but was for a different instance entirely.

What struck me was how much implicit knowledge the user carries about their infrastructure. Three EC2 hosts, multiple PEM files, different usernames per host — none of this was documented anywhere I could find. Now that I've saved the connection details to memory, future sessions won't have this friction. The actual edit took 30 seconds; the SSH detective work took 10 minutes. That ratio is a clear signal that operational documentation pays dividends.

I also noticed the `cron_run.sh` had a stale path referencing the old `fb-group-scraper` directory name — caught that incidentally and fixed it in the same commit.

## Honest Feedback

1. **SSH key discovery was painful.** I tried four keys across three hosts before getting the right combination. I should have asked the user for connection details upfront instead of guessing — would have saved 80% of the session time.

2. **EC2 and local are out of sync.** The remote path is `/home/ec2-user/fb-group-scraper/` but locally it's `fb-crawler`. The GROUP_IDS list is now manually maintained in two places with no sync mechanism — this will drift. A git pull on EC2 would be cleaner.

3. **No verification step.** I updated the EC2 file via sed but didn't verify the scheduler service is actually running or will pick up the change. Should have checked `systemctl status` or at least `ps aux | grep scheduler`.

## Lessons Learned

- Always ask for SSH credentials rather than guessing — implicit infra knowledge is the biggest time sink.
- Saved EC2 connection details to memory for future sessions.
